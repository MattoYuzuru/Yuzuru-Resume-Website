# Keykomi CV

Личный шаблон CV в духе Jake’s Resume: одна колонка, читаемый текст и спокойная типографика. Новая реализация на Typst, код чужого LaTeX-шаблона не копировался. Данные лежат в `content/resume/resume.yaml`, оформление — в `resume/template.typ`.

Основная тема `paper` — тёплый фон `#f8f8f2` из сайта; альтернативная `white` — белый фон. Основной текст 10.2pt Libertinus Serif; Geologica для заголовков включена в `resume/fonts` с SIL OFL. Заголовок и линия разделены 4pt. По углам — небольшие штрихи, внизу — имя и номер страницы. Выбранные слова выделены Libertinus Semibold600 цветом точки сайта `#7a8b6d`; названия и категории остаются жирнее. Цвет не несёт обязательного смысла.

## Собрать и изменить

Нужны Node26.9+, pnpm12.4.2, Typst0.15.1 и Poppler (`pdfinfo`, `pdftotext`, `pdftoppm`). Из корня:

```sh
pnpm install --frozen-lockfile
pnpm resume
pnpm resume --theme white
pnpm resume --lang en --source resume/examples/engineer.json
pnpm resume:check
```

Обычная сборка создаёт тёплые RU/EN PDF в `output/pdf` и не меняет скачиваемые PDF сайта. Альтернативная тема white добавляет `-white` к имени. `--out-dir /absolute/path` выбирает другой каталог.

В репозитории сайта (не в отдельном архиве шаблона) для обновления обоих PDF из канонического файла используется отдельная команда `pnpm resume:publish`. Она допускает только канонические данные, обе локали и основную тему paper. Сам деплой — следующий отдельный шаг по правилам репозитория.

Человеку достаточно отредактировать YAML; строки не являются кодом Typst. Для другого резюме скопируйте пример JSON/YAML в новый файл и передайте `--source`. В Typst Web можно загрузить `resume/` и `content/`, выбрать `resume/main.typ` главным файлом и редактировать YAML. CLI без Node тоже работает:

```sh
typst compile --root . --font-path resume/fonts --input lang=ru resume/main.typ cv.pdf
```

`--input source=...` в Typst задаётся относительно `resume/main.typ`; `--source` в Node-команде — относительно текущего каталога.

## Формат данных

Текст может быть обычной строкой (одинаковой для выбранных языков) или объектом `{ru: ..., en: ...}`. В Node-сборке отсутствие требуемого перевода даёт ошибку до рендера. Реальный пример структуры — `resume/examples/engineer.json`, с вымышленными данными.

| Поле | Содержание |
|---|---|
| `basics` | Обязательные name, headline, location; необязательные email, phone, links, profile |
| `experience[]` | company, role; необязательные dates, location, bullets[] |
| `projects[]` | name; необязательные subtitle, links.repo/demo, stack[], bullets[] |
| `education[]` | school, degree; необязательные start/end или dates, details[] |
| `skills[]` | category и items[]: подтверждённые самостоятельные компетенции |
| `assisted_skills[]` | category и items[]: подтверждённый практический опыт вместе с AI |
| `languages[]` | name и level |
| `pdf` | filename, max_pages, sections[], project_order[], labels, highlights[], content_highlights[] |

Необязательные разделы можно опускать. `pdf.labels` переопределяет подписи разделов: по умолчанию навыки называются нейтрально. В CV Матвея раздел `technical_radar` объединяет две группы: «Глубоко разбираюсь / работал до AI» и «Активно применял вместе с AI». Вместо него можно оставить отдельные `skills`/`assisted_skills`, но не оба представления сразу. `pdf.sections` задаёт порядок и видимость разделов, `pdf.project_order` — выбранные проекты и их порядок без удаления остальных из исходника. В текущем основном CV: Mnema, AeroChat, BPMN.Space, yuzuru-skills, Guanxi (новое направление Alamo). Консольная игра остаётся в источнике для другой подборки. Для расширенного варианта явно задайте `pdf.max_pages: 2`.

`pdf.highlights` содержит до20 буквальных слов/фраз для акцентов в навыках; `pdf.content_highlights` — отдельный список для профиля и bullets. Это обычный текст, а не код или регулярные выражения. Акценты не добавляют новые навыки и не меняют группу компетенций. Выбирайте небольшой набор под роль; не выделяйте всё резюме.

Если текст не помещается, сборка откажется завершаться: она не уменьшает шрифт автоматически, не обрезает пункты и не выбрасывает проекты. Отредактируйте содержание, выбор проектов или лимит страниц. Длинная запись может продолжаться на следующей странице. После каждого изменения содержания нужно осмотреть свежий рендер.

Тесты проверяют другую персону, пропуски необязательных блоков, буквальные #/_/скобки, RU/EN, одну и две страницы, отказ при переполнении и неизменность PDF сайта при preview-сборке. Это проверка шаблона и текстового слоя; универсальная совместимость со всеми ATS не заявляется.

## Использовать с ИИ

Дайте агенту `resume/AI-GUIDE.md`, исходные факты и задачу. Например: «Используй Keykomi CV, подготовь RU/EN версию под backend-вакансию из этого файла; оформление сохрани, неподтверждённые навыки не добавляй».

Typst умеет читать YAML напрямую: https://typst.app/docs/reference/data-loading/yaml/. Шрифт и лицензия: `resume/fonts/SOURCE.md`, `resume/fonts/OFL.txt`.
